# 06. PowerShell용 Git 명령어 치트시트

명령을 외우기보다 **목적 → 실행 → 확인** 순서로 사용하세요. 특히 `git status`는 작업 전후에 반복해서 실행해도 안전합니다.

## 1. PowerShell에서 위치와 파일 확인

| 목적 | 명령 |
|---|---|
| 현재 위치 확인 | `Get-Location` |
| 파일 목록 확인 | `Get-ChildItem` |
| 숨김 파일까지 확인 | `Get-ChildItem -Force` |
| 폴더 이동 | `Set-Location 'C:\경로\프로젝트'` |
| 상위 폴더로 이동 | `Set-Location ..` |
| 폴더 만들기 | `New-Item -ItemType Directory -Path '폴더명'` |
| 빈 파일 만들기 | `New-Item -ItemType File -Path '파일명'` |
| 파일 읽기 | `Get-Content '파일명'` |
| 한 줄 추가 | `Add-Content -Encoding utf8 '파일명' '추가할 내용'` |

경로에 공백이 있으면 반드시 따옴표로 감쌉니다.

```powershell
Set-Location 'C:\Users\Student\My Projects\hello-git'
```

## 2. 최초 한 번 설정

```powershell
git --version
git config --global user.name "내 이름"
git config --global user.email "내 이메일"
git config --global init.defaultBranch main
git config --global --list
```

| 명령 | 의미 |
|---|---|
| `git --version` | 설치된 Git 버전 확인 |
| `git config --global ...` | 현재 Windows 사용자에게 적용할 기본 설정 |
| `git config --local ...` | 현재 저장소에만 적용할 설정 |

## 3. 저장소 시작과 복제

| 목적 | 명령 | 결과 |
|---|---|---|
| 현재 폴더를 저장소로 시작 | `git init -b main` | `.git` 폴더 생성 |
| 원격 저장소 복제 | `git clone <URL>` | 새 폴더, 전체 이력, `origin` 생성 |
| 다른 폴더명으로 복제 | `git clone <URL> <폴더명>` | 지정한 이름의 폴더 생성 |
| 저장소 최상위 경로 확인 | `git rev-parse --show-toplevel` | 현재 저장소 루트 출력 |

`<URL>`과 `<폴더명>`의 꺾쇠는 입력하지 않습니다.

전체 복제 실습과 Private 저장소·fork·submodule clone은 [Clone(복제) 완전 가이드](./03_1_Clone_복제_가이드.md)를 참고하세요.

## 4. 가장 자주 쓰는 상태·차이 확인

```powershell
git status
git diff
git diff --staged
git log --oneline --decorate -10
git log --oneline --graph --decorate --all
```

| 명령 | 보여 주는 것 |
|---|---|
| `git status` | 현재 브랜치, staged/modified/untracked 상태 |
| `git diff` | 아직 stage하지 않은 내용 차이 |
| `git diff --staged` | 다음 커밋에 들어갈 내용 차이 |
| `git log --oneline` | 커밋 이력을 한 줄씩 표시 |
| `git show <커밋>` | 특정 커밋의 정보와 변경 |

## 5. 기본 저장 순서: add → commit → push

```powershell
git status
git diff
git add <파일명>
git diff --staged
git commit -m "변경 목적을 설명하는 메시지"
git push
```

| 명령 | 의미 |
|---|---|
| `git add README.md` | 해당 파일의 현재 변경을 stage |
| `git add file1 file2` | 지정한 여러 파일을 stage |
| `git add .` | 현재 폴더 아래의 모든 변경을 stage하므로 실행 전 확인 필수 |
| `git commit -m "..."` | staged 변경으로 로컬 커밋 생성 |
| `git push` | 추적 중인 원격 브랜치로 커밋 전송 |

커밋 메시지 예:

```text
Add signup validation
Fix total price calculation
Update Windows setup guide
Remove unused sample data
```

`update`, `work`, `수정`처럼 범위가 불분명한 말만 쓰기보다 무엇이 달라졌는지 적습니다.

## 6. 원격 저장소와 동기화

```powershell
git remote -v
git fetch origin
git pull --ff-only
git push
```

| 목적 | 명령 |
|---|---|
| 원격 목록과 주소 확인 | `git remote -v` |
| `origin` 추가 | `git remote add origin <URL>` |
| `origin` 주소 변경 | `git remote set-url origin <URL>` |
| 원격 이력만 가져오기 | `git fetch origin` |
| 현재 브랜치 최신화 | `git pull --ff-only` |
| 첫 브랜치 push와 추적 설정 | `git push -u origin <브랜치>` |
| 사라진 원격 브랜치 참조 정리 | `git fetch --prune` |

`fetch`는 원격 상태를 가져오기만 하고, `pull`은 가져온 변경을 현재 브랜치에 반영합니다.

## 7. 브랜치와 병합

```powershell
git branch
git switch main
git switch -c feature/example
git merge feature/example
git branch -d feature/example
```

| 목적 | 명령 |
|---|---|
| 현재 브랜치 이름 | `git branch --show-current` |
| 로컬 브랜치 목록 | `git branch` |
| 로컬·원격 브랜치 목록 | `git branch --all` |
| 새 브랜치 생성과 이동 | `git switch -c <새-브랜치>` |
| 기존 브랜치 이동 | `git switch <브랜치>` |
| 직전 브랜치로 이동 | `git switch -` |
| 현재 브랜치에 병합 | `git merge <가져올-브랜치>` |
| 진행 중 merge 취소 | `git merge --abort` |
| 병합된 로컬 브랜치 삭제 | `git branch -d <브랜치>` |
| 원격 브랜치 삭제 | `git push origin --delete <브랜치>` |

병합 방향을 기억하세요.

```powershell
# feature의 변경을 main이 받도록 병합
git switch main
git merge feature/example
```

## 8. 안전한 되돌리기

| 상황 | 먼저 확인 | 명령 | 주의 |
|---|---|---|---|
| stage만 취소 | `git diff --staged` | `git restore --staged <파일>` | 실제 수정 내용은 유지 |
| 커밋 전 파일 수정 폐기 | `git diff` | `git restore <파일>` | 수정 내용이 사라짐 |
| 방금 커밋 메시지 수정 | `git log -1` | `git commit --amend -m "새 메시지"` | 아직 push하지 않은 커밋에만 권장 |
| 공유한 커밋 취소 | `git log --oneline` | `git revert <커밋>` | 취소 내용을 새 커밋으로 남김 |
| merge 진행 취소 | `git status` | `git merge --abort` | 충돌 해결 커밋 전 사용 |

`git restore <파일>`은 커밋하지 않은 수정 내용을 버립니다. 실행 전 `git diff`를 읽고 정말 필요 없는 변경인지 확인하세요.

## 9. 잠깐 작업 보관하기: stash

브랜치를 바꿔야 하지만 아직 커밋하기 어려운 변경을 잠시 보관할 때 사용합니다.

```powershell
git status
git stash push -m "WIP: login form"
git stash list
git switch main
```

돌아와 다시 적용합니다.

```powershell
git switch feature/login
git stash pop
git status
```

`stash pop`도 충돌할 수 있습니다. 장기간 보관소로 쓰지 말고, 목적이 완성되면 커밋하는 편이 좋습니다.

## 10. `.gitignore` 기본 예시

Python 학습 프로젝트라면 저장소를 시작할 때 다음과 같은 파일을 만들 수 있습니다.

```powershell
@'
# 비밀 설정
.env
.env.*

# Python
.venv/
__pycache__/
*.py[cod]
.ipynb_checkpoints/

# 운영체제·편집기 임시 파일
Thumbs.db
.DS_Store
'@ | Set-Content -Encoding utf8 .gitignore
```

프로젝트마다 필요한 패턴만 사용하세요. `.gitignore`에 추가하기 전에 이미 커밋한 파일은 자동으로 추적 해제되지 않습니다.

## 11. 개인 작업의 하루 흐름

```powershell
# 시작할 때
git switch main
git pull --ff-only

# 작업 중과 커밋 전
git status
git diff
git add <파일명>
git diff --staged
git commit -m "Explain one completed change"

# GitHub에 보낼 때
git push
git status
```

## 12. 팀 작업의 하루 흐름

```powershell
# 최신 main에서 작업 브랜치 생성
git switch main
git pull --ff-only
git switch -c feature/short-name

# 작업, 확인, 커밋
git status
git diff
git add <파일명>
git diff --staged
git commit -m "Explain one completed change"

# 브랜치를 올리고 GitHub에서 PR 생성
git push -u origin feature/short-name

# PR 병합 후 로컬 정리
git switch main
git pull --ff-only
git branch -d feature/short-name
git fetch --prune
```

## 13. 초보자가 피할 명령

다음 명령은 유용하지만 변경을 잃거나 공유 이력을 망가뜨릴 수 있습니다. 인터넷 답변에서 보더라도 뜻과 영향을 확인하기 전에는 복사해 실행하지 마세요.

```text
git reset --hard
git clean -fd
git push --force
git branch -D <브랜치>
```

문제가 생기면 먼저 `git status`, `git log --oneline --graph --all`, `git remote -v` 결과를 확인하고 [문제 해결 문서](./07_문제해결과_안전수칙.md)를 참고합니다.
